# Arquitectura del Proyecto en Godot

## 1. Sistema de Datos (Resources)
[cite_start]Debemos usar la clase `Resource` de Godot para los datos base[cite: 10].
* [cite_start]**Script:** `SkeletonData.gd` (Hereda de Resource)[cite: 11].
* [cite_start]**Variables:** Nivel/Tier, Nombre, Almas_por_día, HP, Ataque, Defensa, Sprite[cite: 11].
* [cite_start]**Uso:** Crear archivos `.tres` (ej. `Esqueleto_Tier1.tres`) para no quemar datos en el código[cite: 10, 12].

## 2. Gestor Global (Singleton/Autoload)
* [cite_start]**Script:** `GameManager.gd` configurado como Autoload[cite: 17].
* [cite_start]**Responsabilidades:** * Persistir datos entre la catacumba y el combate[cite: 17].
    * [cite_start]Llevar la Economía (Almas) y el Tiempo (Día 1-5, Fase de Preparación/Combate)[cite: 19].
    * [cite_start]Guardar el Inventario (estado del tablero)[cite: 20].
    * [cite_start]Guardar el Equipo de Combate (Array de 3 o 4 esqueletos elegidos)[cite: 21].

## 3. Escena Principal: Catacumba
* [cite_start]**Nodos:** Uso de `GridContainer` con `TextureRect` o `Panel` para los slots de la grilla[cite: 23].
* [cite_start]**Interacción:** Implementar Drag & Drop usando las funciones de Control (`_get_drag_data`, `_can_drop_data`, `_drop_data`)[cite: 24]. [cite_start]Si se suelta sobre el mismo Tier, se borran ambos y se instancia el Tier superior[cite: 25].
* [cite_start]**Transición:** Botón "Avanzar Día" que suma almas, suma 1 al día y, si es día 5, fuerza el paso a la fase de combate[cite: 26, 27, 28].

## 4. Escena Secundaria: Combate
* [cite_start]**Escena:** `CombatScreen.tscn` (separada de la catacumba)[cite: 29].
* [cite_start]**Lógica:** Instanciar aventureros enemigos según el nivel de batalla (1 a 5) y cargar a los aliados desde el `GameManager`[cite: 30, 31].
* [cite_start]**Flujo:** Máquina de estados básica (Turno Jugador -> Turno Enemigo)[cite: 32].
